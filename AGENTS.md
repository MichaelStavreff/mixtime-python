# AGENTS.md

Ports of an R package to Python, Rust, and C++. A port is correct when it
reproduces the R package's behavior, not when it looks idiomatic on its own.

## Layout

```
upstream/<pkg>/          # pristine R sources — read-only, source of truth
rust/                    # cargo crate + PyO3 bindings, built with maturin
python/                  # uv project (pyproject.toml)
cpp/                     # CMake project using scikit-build-core
fixtures/                # golden outputs generated from the R original
benchmarks/              # cross-language benchmark scripts
justfile                 # single entrypoint for all tasks
```

## Non-negotiables

- Never edit `upstream/`. If a port and the R original disagree, the port is
  wrong.
- Fixtures are generated by running the R original. Do not hand-write expected
  values or copy them from another port.
- Ports do not import or share code with each other; each stays idiomatic for
  its ecosystem.
- Document intentional divergences in `<lang>/README.md`. Never silently loosen
  a numeric tolerance to make a test pass.

## R semantics that bite

These cause silent wrong answers, not crashes:

- **Indexing**: R is 1-based and inclusive. Convert to 0-based half-open
  deliberately; boundary loops are the usual off-by-one.
- **`NA` is not `NaN` and not `NULL`**: `NA` is typed (`NA_integer_`,
  `NA_real_`, `NA_character_`) and propagates; `NULL` means absence. Map each
  explicitly (`None`, `Option`, `std::optional`) and preserve propagation.
- **Recycling**: R recycles shorter vectors, warning only when lengths are not
  multiples. Decide per function whether to replicate, warn, or error — do not
  let broadcasting do it implicitly.
- **Copy-on-modify**: R values are copied on assignment; Python/Rust/C++ references
  are not. Code that mutates an argument can corrupt caller state where R would
  not.
- **Numbers are doubles unless suffixed `L`**: R integer literals are 32-bit,
  `numeric` is double. Comparing with `identical()` also checks type, so
  returning `int` where R returns `double` is a behavior change.
- **Matrix layout**: R matrices are column-major. Contiguous C++/Rust buffers
  and NumPy defaults differ; transpose or index accordingly.
- **`drop = TRUE`**: extracting a single row/column from a matrix returns a
  vector by default. Preserve that unless an API-compatible option exists.
- **Factors**: level ordering, unused levels, and `NA` levels are observable.
  `stringsAsFactors` defaults differ from every target language.
- **RNG**: `set.seed()` uses R's Mersenne-Twister plus inversion sampling;
  `numpy.random`/`rand` defaults will not match. Either freeze RNG-dependent
  fixtures or document the incompatibility.

## Verification workflow

1. Regenerate fixtures by running the R original: `just fixtures`.
2. Run the tests against the fixtures: `just test`.
3. If output differs, fix the port or document the divergence — do not weaken
   the fixture.

Regenerating fixtures requires a local R installation. If the package lives in
a non-default R library, pass `R_LIBS` (e.g.
`R_LIBS=/tmp/opencode/Rlib just fixtures`). CI does not need R unless it
regenerates fixtures.

## Commands

`just` is the single entrypoint; `just --list` shows all recipes.

| Task | Recipe |
| --- | --- |
| Build the Rust extension and sync the Python env | `just build` |
| Rust unit tests | `just test-rust` |
| Python fixture tests | `just test-python` |
| All tests | `just test` |
| Regenerate R fixtures | `just fixtures` |
| Clean build/test artifacts | `just clean` |

`test-python` depends on `build`, so Rust changes are rebuilt before pytest
runs. Python commands run through `uv` inside `python/`; do not use a global
Python environment.

## Git and CI

- `main` is protected. Branch as `feat/<topic>` for changes.
- Conventional Commits, e.g. `feat: add port for <pkg>`.
- Merge gate: CI green, including `cargo test` and `pytest`.
- No CI gate is defined yet for C++ ports; add one before the first C++ port
  merges.
