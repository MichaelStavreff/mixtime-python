# mixtime-python

A Pythonic time-vector package for mixed-granularity temporal data, ported from
R's [**mixtime**](https://github.com/mitchelloharawild/mixtime) package. The
arithmetic kernel is Rust; the time model, parsing, formatting, calendars, and
timezone handling are Python.

> **Status:** niche MVP. The package now provides Gregorian and ISO-week time
> vectors, parsing and formatting, cyclical components, durations, rounding,
> sequences, arithmetic, timezone-aware `datetime`, type and completeness
> predicates, component extraction/composition, and optional pandas interop.
> Non-Gregorian calendars, astronomical calendars, and the full R format-token
> language remain out of scope. See [Scope](#scope) and
> [`DECISION.md`](DECISION.md).

## What it does

mixtime represents time points as counts of *chronons*: days, months, years, and
so on. The port keeps that model but exposes it through Python classes rather
than R's S7/vctrs system.

There are two layers:

- **Python time model** — `yearmonth`, `yearquarter`, `yearweek`, `date`,
  `datetime`, cyclical components such as `month_of_year`, durations such as
  `months(1)`, a `Mixtime` container for mixed granularities, component helpers
  (`lin`, `cyc`, `time_components`, `time_compose`), and predicates such as
  `time_is_determinate_at` and `time_is_complete_at`.
- **Rust kernel** — the low-level Gregorian chronon splits (`day_to_month`,
  `month_to_day`, ...), still available as NumPy-in/NumPy-out functions.

The high-level API is deliberately Pythonic. Observable Gregorian chronon
semantics are kept compatible with mixtime 0.4.0; intentional divergences are
listed in [`python/README.md`](python/README.md#divergences-from-r).

## Quick start

Prerequisites:

- Rust toolchain (`cargo`, `rustc`)
- Python 3.9+
- [`uv`](https://docs.astral.sh/uv/)
- `just` (optional)

```sh
git clone https://github.com/MichaelStavreff/mixtime-python.git
cd mixtime-python/python
uv sync --reinstall-package mixtime-rs
```

`uv sync` builds the Rust extension with maturin and installs the local
`mixtime` package into the project environment. Run it from `python/`; the
Python project lives there, and the Rust crate is resolved as a path
dependency. `pip install` is not supported for the same reason.

Run Python inside the project environment with `uv run`:

```sh
uv run python -c "import mixtime as mt; print(mt.yearmonth(['2024-01', '2024-02']))"
```

### Optional: the `just` task runner

The repository includes a [`justfile`](justfile) for
[`just`](https://github.com/casey/just), a small command runner. It is a
convenience only; the underlying commands are shown in the Quick start and
Development sections.

```sh
just build   # cd python && uv sync --reinstall-package mixtime-rs
just test    # cargo test, then rebuild the extension and run pytest
```

## Usage

### Time vectors

```python
import mixtime as mt

months = mt.yearmonth(["2024-01", "2024-02", "2024-03"])
print(months.values)    # [648 649 650]  (months since 1970-01)
print(months.format())  # ['2024 Jan', '2024 Feb', '2024 Mar']

dates = mt.date(["2024-01-15", "2024-02-29"])
print(dates.values)     # [19737 19782]  (days since 1970-01-01)
print(dates.format())   # ['2024-01-15', '2024-02-29']
```

Constructors accept strings, `datetime.date`, `datetime.datetime`,
`numpy.datetime64`, existing time vectors, and one-dimensional pandas
`Series`/`Index` objects. Numeric
input is interpreted as chronon counts since the Unix epoch. Integer counts,
strings, and temporal objects default to discrete chronons; floating-point
counts default to continuous chronons. Pass `discrete=` explicitly to override
that inference.

### Cyclical components

```python
when = mt.date(["2024-01-15", "2024-02-29", "2024-12-31"])

print(mt.month_of_year(when).format())  # ['Jan', 'Feb', 'Dec']
print(mt.day_of_week(when).format())    # ['Mon', 'Thu', 'Tue']
print(mt.day_of_year(when).format())    # ['D15', 'D60', 'D366']
print(mt.week_of_year(when).format())   # ['W03', 'W09', 'W01']
```

### Durations, arithmetic, rounding, and sequences

```python
x = mt.yearmonth(["2024-01", "2024-02", "2024-07", "2024-12"])

print((x + mt.months(1)).format())
print((x - mt.yearmonth("2023-12")).format())  # duration in months
print(mt.time_floor(x, "year").format())
print(mt.time_ceiling(x, "year").format())
print(mt.seq(mt.yearmonth("2024-01"), mt.yearmonth("2024-06"), by=2).format())
```

`time_floor`, `time_ceiling`, and `time_round` accept a unit name, a unit object
such as `mt.cal_gregorian.year`, a duration such as `mt.years(1)`, or a time
vector whose chronon is used.

Durations are continuous by default, matching R's double-valued helpers:
`mt.years(1)` formats as `1.0 years`. Pass `discrete=True` for whole-granule
durations, such as `mt.years(1, discrete=True)`.

### Mixed granularity

```python
mixed = mt.mixtime(
    mt.yearmonth(["2024-01", "2024-02"]),
    mt.yearquarter(["2024-Q2", "2024-Q3"]),
)
print(mixed.format())
# ['2024 Jan', '2024 Feb', '2024 Q2', '2024 Q3']
```

Each part keeps its own chronon, cycle, calendar, and timezone.

### Timezones

`datetime` values are stored as UTC seconds since the epoch. Pass `tz=` to
interpret naive input and to format in a named zone:

```python
import mixtime as mt

x = mt.datetime("2024-01-15 12:34:56", tz="UTC")
y = mt.datetime("2024-01-15 12:34:56+11:00", tz="Australia/Sydney")
print(y.format())
```

### Components

`time_components()` extracts linear and cyclical parts, and `time_compose()`
builds time points back from them. `cyc()` values are 1-indexed positions within
the cycle.

```python
when = mt.datetime("2024-03-15 12:34:56")
parts = mt.time_components(
    when,
    year=mt.lin("year"),
    month=mt.cyc("month", "year"),
    day=mt.cyc("day", "month"),
)
print(parts["month"].format())  # ['Mar']
print(mt.time_compose(
    mt.lin("year", 1980),
    mt.cyc("month", "year", 3),
    mt.cyc("day", "month", 15),
).format())  # ['1980-03-15']
```

### Predicates

```python
x = mt.yearmonth(["2024-01", "2024-02"])
print(mt.time_is_linear(x))                 # [ True  True]
print(mt.time_is_determinate_at(x, "year")) # [True True]
print(mt.time_is_complete_at(x, "year"))    # [False False]
```

`time_is_determinate_at()` tests whether a discrete time point can resolve a
granule; continuous time points resolve every granule. `time_is_complete_at()`
tests whether the vector contains every finer chronon of each coarser granule.
Missing and infinite values are reported as `None`.

### pandas interop

pandas is optional. Install the extra, pass a one-dimensional `Series`/`Index`
to a constructor, or call `to_pandas()`:

```sh
uv add "mixtime[pandas]"
```

```python
import pandas as pd

x = mt.date(pd.Series(["2024-01-15", None]))
print(x.format())  # ['2024-01-15', 'NA']

idx = mt.yearmonth(["2024-01", "2024-02"]).to_pandas()
```

### Low-level Rust kernel

The original NumPy kernel remains available:

```python
import numpy as np
import mixtime

days = np.array([0.0, 59.0, 60.0, 365.0])
months, offsets = mixtime.day_to_month(days)
```

Each kernel function takes a one-dimensional `float64` NumPy array and returns
two `float64` arrays, `(div, mod)`. The input buffer is read directly, and the
output arrays are filled directly by Rust.

| Function | Conversion |
|---|---|
| `day_to_month(x, from_n=1.0, to_n=1.0)` | day → month |
| `day_to_quarter(x, from_n=1.0)` | day → quarter (3-month blocks) |
| `day_to_year(x, from_n=1.0, to_n=1.0)` | day → year |
| `month_to_day(x, from_n=1.0, to_n=1.0)` | month → day |
| `year_to_day(x, from_n=1.0, to_n=1.0)` | year → day |

## Scope

Ported:

- Gregorian linear time at year, quarter, month, day, and second granularity
- ISO week time (`yearweek`, `week_of_year`) using R's Thursday-anchored week
  chronons
- parsing and default formatting for common Gregorian formats
- cyclical components (`month_of_year`, `day_of_year`, `day_of_month`,
  `day_of_week`, `week_of_year`, `time_of_day`)
- durations (`years`, `quarters`, `months`, `weeks`, `days`, `hours`,
  `minutes`, `seconds`, `milliseconds`)
- time arithmetic, comparison, rounding, and sequences, including continuous
  same-category shifts and common-chronon differences
- UTC and IANA timezone-aware `datetime`
- type predicates and granule determinacy/completeness predicates
- Gregorian component extraction and composition (`time_components`,
  `time_compose`, `lin`, `cyc`)
- optional pandas `Series`/`Index` input and `PeriodIndex`/`DatetimeIndex`
  output
- the low-level Rust chronon splits

Not yet ported:

- Symmetry454, civil/lunar/solar/astronomical calendars
- the full R format-token language and all labelled parsing variants
- the complete vctrs/S7 coercion surface
- ggplot2 and tsibble integration
- complete `Mixtime` arithmetic and columnar pandas/DataFrame coercion
- continuous calendar/fixed cross-category shifts (for example,
  `date + months(1)`) and calendar-step `seq()` on day/second time
- R's `seq(from, length.out=, by=)` form

See [`COVERAGE.md`](COVERAGE.md) for the R branch-to-test map and
[`DECISION.md`](DECISION.md) for the scope decision.

low-level kernel. The port is faster than R at every measured size from 0 to
2,097,152 elements; see [`DECISION.md`](DECISION.md) for the raw results.
