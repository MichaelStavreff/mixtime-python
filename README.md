# mixtime-python

A Pythonic time-vector package for mixed-granularity temporal data, ported from
R's [**mixtime**](https://github.com/mitchelloharawild/mixtime) package. The
arithmetic kernel is Rust; the time model, parsing, formatting, calendars, and
timezone handling are Python.

> **Status:** niche MVP. The package now provides Gregorian and ISO-week time
> vectors, parsing and formatting, cyclical components, durations, rounding,
> calendar-aware sequences, arithmetic, DST-aware calendar shifts,
> timezone-aware `datetime`,
> timezone name/offset helpers and transitions, type and completeness
> predicates, component extraction/composition, chronon bounds, circular sums,
> scalar values, and an optional pandas `"mixtime"` extension dtype for
> Series/DataFrame columns, including Arrow/Parquet round-trips. Non-Gregorian
> calendars, astronomical calendars, and the full R format-token language
> remain out of scope. See [Scope](#scope) and [`DECISION.md`](DECISION.md).

## What it does

mixtime represents time points as counts of *chronons*: days, months, years, and
so on. The port keeps that model but exposes it through Python classes rather
than R's S7/vctrs system.

There are two layers:

- **Python time model** — `yearmonth`, `yearquarter`, `yearweek`, `date`,
  `datetime`, cyclical components such as `month_of_year`, durations such as
  `months(1)`, a `Mixtime` container for mixed granularities, component helpers
  (`lin`, `cyc`, `time_components`, `time_compose`), chronon bounds
  (`chronon_glb`, `chronon_lub`), metadata accessors (`time_chronon`,
  `time_cycle`, `time_calendar`, `is_mixtime`), timezone helpers (`tz_name`,
  `tz_abbreviation`, `tz_offset`, `tz_transitions`), scalar values
  (`TimeScalar`, `.scalar(i)`), predicates such as `time_is_determinate_at`
  and `time_is_complete_at`, mixed-vector comparison/ordering
  (`Mixtime.sort`, `argsort`, `min`, `max`), and an optional pandas extension
  dtype.
- **Rust kernel** — the low-level Gregorian chronon splits (`day_to_month`,
  `month_to_day`, ...), still available as NumPy-in/NumPy-out functions.

The high-level API is deliberately Pythonic. Observable Gregorian chronon
semantics are kept compatible with mixtime 0.4.0; intentional divergences are
listed in [`python/README.md`](python/README.md#divergences-from-r).

## Quick start

Prerequisites:

- Rust toolchain (`cargo`, `rustc`)
- Python 3.9+
- [`uv`](https://docs.astral.sh/uv/)
- `just` (optional)

```sh
git clone https://github.com/MichaelStavreff/mixtime-python.git
cd mixtime-python/python
uv sync --reinstall-package mixtime-rs
```

`uv sync` builds the Rust extension with maturin and installs the local
`mixtime` package into the project environment. Run it from `python/`; the
Python project lives there, and the Rust crate is resolved as a path
dependency. `pip install` is not supported for the same reason.

Run Python inside the project environment with `uv run`:

```sh
uv run python -c "import mixtime as mt; print(mt.yearmonth(['2024-01', '2024-02']))"
```

### Optional: the `just` task runner

The repository includes a [`justfile`](justfile) for
[`just`](https://github.com/casey/just), a small command runner. It is a
convenience only; the underlying commands are shown in the Quick start and
Development sections.

```sh
just build   # cd python && uv sync --reinstall-package mixtime-rs
just test    # cargo test, then rebuild the extension and run pytest
```

## Usage

### Time vectors

```python
import mixtime as mt

months = mt.yearmonth(["2024-01", "2024-02", "2024-03"])
print(months.values)    # [648 649 650]  (months since 1970-01)
print(months.format())  # ['2024 Jan', '2024 Feb', '2024 Mar']

dates = mt.date(["2024-01-15", "2024-02-29"])
print(dates.values)     # [19737 19782]  (days since 1970-01-01)
print(dates.format())   # ['2024-01-15', '2024-02-29']
```

Constructors accept strings, `datetime.date`, `datetime.datetime`,
`numpy.datetime64`, existing time vectors, and one-dimensional pandas
`Series`/`Index` objects. Numeric
input is interpreted as chronon counts since the Unix epoch. Integer counts,
strings, and temporal objects default to discrete chronons; floating-point
counts default to continuous chronons. Pass `discrete=` explicitly to override
that inference.

### Cyclical components

```python
when = mt.date(["2024-01-15", "2024-02-29", "2024-12-31"])

print(mt.month_of_year(when).format())  # ['Jan', 'Feb', 'Dec']
print(mt.day_of_week(when).format())    # ['Mon', 'Thu', 'Tue']
print(mt.day_of_year(when).format())    # ['D15', 'D60', 'D366']
print(mt.week_of_year(when).format())   # ['W03', 'W09', 'W01']
```

### Durations, arithmetic, rounding, and sequences

```python
x = mt.yearmonth(["2024-01", "2024-02", "2024-07", "2024-12"])

print((x + mt.months(1)).format())
print((x - mt.yearmonth("2023-12")).format())  # duration in months
print(mt.time_floor(x, "year").format())
print(mt.time_ceiling(x, "year").format())
print(mt.seq(mt.yearmonth("2024-01"), mt.yearmonth("2024-06"), by=2).format())
print(
    mt.seq(mt.date("2024-01-31"), mt.date("2024-05-31"), by="month").format()
)
# ['2024-01-31', '2024-02-29', '2024-03-31', '2024-04-30', '2024-05-31']
```

`time_floor`, `time_ceiling`, and `time_round` accept a unit name, a unit object
such as `mt.cal_gregorian.year`, a duration such as `mt.years(1)`, or a time
vector whose chronon is used.

For `date` and `datetime`, `seq()` accepts day, week, month, quarter, and year
steps as a duration, unit, or string (`"month"`, `"1 month"`, `"3 days"`). These
steps use anchor-based calendar shifts: day/week sequences preserve local
wall-clock time across DST changes, and month/quarter/year sequences clamp
month ends. Month-like endpoint alignment follows R, so a clamped endpoint can
be excluded when the end is earlier in its month/quarter/year than the start.
For example, `seq(date("2024-01-31"), date("2024-04-30"), by="month")` stops at
`2024-03-31`, while ending on `2024-05-31` includes all five month ends.

Durations are continuous by default, matching R's double-valued helpers:
`mt.years(1)` formats as `1.0 years`. Pass `discrete=True` for whole-granule
durations, such as `mt.years(1, discrete=True)`.

Day-or-longer shifts on `date` and `datetime` use calendar fields. For a
timezone-aware `datetime`, day and week shifts preserve the local wall-clock
time across DST changes, while sub-day durations add elapsed time. Month,
quarter, and year shifts clamp the day to the target month:

```python
ny = mt.datetime("2024-03-09 12:00:00", tz="America/New_York")
print((ny + mt.days(1)).format())    # ['2024-03-10 12:00:00 EDT']
print((ny + mt.hours(24)).format())  # ['2024-03-10 13:00:00 EDT']
print((mt.date("2024-01-31") + mt.months(1)).format())  # ['2024-02-29']
```

DST gaps and ambiguous local times use R's default clamp behavior: a skipped
local time moves back by the gap, and an ambiguous time resolves to its first
occurrence. Shifts requiring a fractional month (including fractional
quarters) are not implemented; fractional years that resolve to whole months
are allowed.

### Mixed granularity

```python
mixed = mt.mixtime(
    mt.yearmonth(["2024-01", "2024-02"]),
    mt.yearquarter(["2024-Q2", "2024-Q3"]),
)
print(mixed.format())
# ['2024 Jan', '2024 Feb', '2024 Q2', '2024 Q3']
```

Each part keeps its own chronon, cycle, calendar, and timezone.

Subtracting two mixed vectors is elementwise and returns a mixed vector of
durations. Each pair uses its finest common chronon; a length-one operand is
recycled, and discrete operands with different chronons raise rather than
silently choosing an anchor.

```python
later = mt.mixtime(mt.yearmonth(["2024-02"]), mt.year(["2025"]))
earlier = mt.mixtime(mt.yearmonth(["2024-01"]), mt.year(["2024"]))
print((later - earlier).format())  # ['1.0 months', '1.0 years']
```

### Mixed comparison and ordering

Time points compare as half-open intervals: a discrete value spans its whole
granule, while a continuous value is an instant. Comparisons across
granularities therefore follow R's interval relations rather than comparing
converted start values.

```python
import mixtime as mt

mixed = mt.mixtime(
    mt.yearmonth(["2024-01", "2024-02"]),
    mt.year(["2024", "2025"]),
)
print(mixed.sort().format())   # ['2024 Jan', '2024 Feb', '2024', '2025']
print(mixed.min().format())    # 2024 Jan
print(mixed.max().format())    # 2025 Jan

months = mt.month_of_year(["2024-12-15", "2025-01-15", "2024-06-15"])
print(months.sort().format())  # ['Jan', 'Jun', 'Dec']
```

`TimeVector.sort()`/`argsort()` order one granularity directly; cyclical
vectors order by position within the cycle. `Mixtime.sort()`/`argsort()` use
R's mixed order proxy: parts convert to their finest shared chronon, discrete
values shift by half a chronon so a span sorts at its midpoint, and cyclical
parts order by position within the cycle. `Mixtime` comparisons broadcast a
length-one operand and raise on other length mismatches. Missing values
compare equal in `==` masks; ordering comparisons involving a missing value
are `False`, where R would return `NA`. `TimeVector.min()`/`max()` and
`Mixtime.min()`/`max()` return a `TimeScalar`, skip missing values by default,
and accept `skipna=False` for R's `na.rm = FALSE` behaviour.

### pandas columns

pandas is optional; install the extra with `uv add "mixtime[pandas]"` (or the
equivalent `pip` extra). `to_pandas_series()` returns a Series backed by the
`"mixtime"` extension dtype, including mixed-granularity `Mixtime` columns:

```python
import pandas as pd
import mixtime as mt

when = mt.mixtime(
    mt.yearmonth(["2024-01", "2024-02"]),
    mt.date(["2024-03-01", None]),
)
series = when.to_pandas_series(name="when")
frame = pd.DataFrame({"when": series, "value": [1, 2, 3, 4]})

print(series.dtype)                  # mixtime
print(series.iloc[0])                # 2024 Jan (a TimeScalar)
print(series.iloc[0].chronon.name)   # month
print(frame["when"].isna().tolist()) # [False, False, False, True]
```

`pd.Series(mt.MixtimeArray(when))` is equivalent. The extension array supports
missing values, slicing, `take`, `fillna`, `where`, `concat`, `shift()`/`diff()`,
`cummin()`/`cummax()`, `astype(str)`/`astype("string")`, duration shifts, mixed
time-point differences, and object-array conversion. Mixed-granularity columns
sort
chronologically, and comparisons, `between()`, `min()`/`max()`,
`idxmin()`/`idxmax()`, `groupby()`, `merge()`, `drop_duplicates()`, and
`unique()` follow the core interval rules. `MixtimeArray.nlargest()` and
`nsmallest()` are available directly; pandas' `Series.nlargest()`/`nsmallest()`
reject non-numeric extension dtypes, so use
`series.sort_values(ascending=False).head(n)` instead. Constructors also accept
one-dimensional pandas `Series`/`Index` inputs, and `to_pandas()` is unchanged:
it still returns a `PeriodIndex`/`DatetimeIndex` for linear time.

Arrow and Parquet export require `pyarrow`; install `mixtime[pandas,arrow]` or
add `pyarrow` separately. A mixtime column is written as a struct that keeps
the chronon, cycle, calendar, timezone, discreteness, and missing values, so
`DataFrame.to_parquet()` and `pd.read_parquet()` round-trip back to the
`"mixtime"` extension dtype instead of formatted strings.

### Timezones

`datetime` values are stored as UTC seconds since the epoch. Pass `tz=` to
interpret naive input and to format in a named zone:

```python
import datetime as dt
from zoneinfo import ZoneInfo

import mixtime as mt

x = mt.datetime("2024-01-15 12:34:56", tz="UTC")
y = mt.datetime("2024-01-15 12:34:56+11:00", tz="Australia/Sydney")
print(y.format())

ny = mt.datetime("2024-07-15 12:00:00", tz="America/New_York")
print(mt.tz_name(ny))          # ['America/New_York']
print(mt.tz_abbreviation(ny))  # ['EDT']
print(mt.tz_offset(ny).format())  # ['-14400.0 seconds']

changes = mt.tz_transitions(
    dt.datetime(2024, 1, 1, tzinfo=ZoneInfo("America/New_York")),
    dt.datetime(2024, 12, 31, tzinfo=ZoneInfo("America/New_York")),
)
print(changes["time"].format())
# ['2024-03-10 07:00:00 0.0%', '2024-11-03 06:00:00 0.0%']
```

`tz_name()` returns `None` for naive time; `tz_abbreviation()` returns an empty
string there, matching R. `tz_offset()` returns a `Duration` in each element's
own chronon: seconds for `datetime`, days for `date`, months for `yearmonth`,
and so on. Default `datetime` formatting appends the zone abbreviation for
non-UTC named zones, matching R.

### Components

`time_components()` extracts linear and cyclical parts, and `time_compose()`
builds time points back from them. `cyc()` values are 1-indexed positions within
the cycle.

```python
when = mt.datetime("2024-03-15 12:34:56")
parts = mt.time_components(
    when,
    year=mt.lin("year"),
    month=mt.cyc("month", "year"),
    day=mt.cyc("day", "month"),
)
print(parts["month"].format())  # ['Mar']
print(mt.time_compose(
    mt.lin("year", 1980),
    mt.cyc("month", "year", 3),
    mt.cyc("day", "month", 15),
).format())  # ['1980-03-15']
```

### Chronon bounds

`chronon_glb()` returns the closest common chronon no coarser than every input;
`chronon_lub()` returns the closest common chronon no finer than every input.

```python
print(mt.chronon_glb(mt.yearmonth("2024-01"), mt.date("2024-01-01")))  # 1 day
print(mt.chronon_lub(mt.yearmonth("2024-01"), mt.date("2024-01-01")))  # 1 month
print(mt.circsum([1, 2, 3, 4], 2, 2))  # [3. 7.]
```

### Predicates

```python
x = mt.yearmonth(["2024-01", "2024-02"])
print(mt.time_is_linear(x))                 # [ True  True]
print(mt.time_is_determinate_at(x, "year")) # [True True]
print(mt.time_is_complete_at(x, "year"))    # [False False]
```

`time_is_determinate_at()` tests whether a discrete time point can resolve a
granule; continuous time points resolve every granule. `time_is_complete_at()`
tests whether the vector contains every finer chronon of each coarser granule.
Missing and infinite values are reported as `None`.

### Low-level Rust kernel

The original NumPy kernel remains available:

```python
import numpy as np
import mixtime

days = np.array([0.0, 59.0, 60.0, 365.0])
months, offsets = mixtime.day_to_month(days)
```

Each kernel function takes a one-dimensional `float64` NumPy array and returns
two `float64` arrays, `(div, mod)`. The input buffer is read directly, and the
output arrays are filled directly by Rust.

| Function | Conversion |
|---|---|
| `day_to_month(x, from_n=1.0, to_n=1.0)` | day → month |
| `day_to_quarter(x, from_n=1.0)` | day → quarter (3-month blocks) |
| `day_to_year(x, from_n=1.0, to_n=1.0)` | day → year |
| `month_to_day(x, from_n=1.0, to_n=1.0)` | month → day |
| `year_to_day(x, from_n=1.0, to_n=1.0)` | year → day |

## Scope

Ported:

- Gregorian linear time at year, quarter, month, day, and second granularity
- ISO week time (`yearweek`, `week_of_year`) using R's Thursday-anchored week
  chronons
- parsing and default formatting for common Gregorian formats
- cyclical components (`month_of_year`, `day_of_year`, `day_of_month`,
  `day_of_week`, `week_of_year`, `time_of_day`)
- durations (`years`, `quarters`, `months`, `weeks`, `days`, `hours`,
  `minutes`, `seconds`, `milliseconds`)
- time arithmetic, comparison, rounding, and sequences, including DST-aware
  day/week shifts, clamped month/quarter/year shifts on `date`/`datetime`,
  calendar-aware date/datetime sequences, continuous shifts within a category,
  common-chronon differences, elementwise mixed time-point differences, R's
  half-open interval comparisons, and mixed-granularity
  `Mixtime` sort/argsort/min/max
- UTC and IANA timezone-aware `datetime`, plus `tz_name`, `tz_abbreviation`,
  `tz_offset`, and `tz_transitions`
- type predicates and granule determinacy/completeness predicates
- Gregorian component extraction and composition (`time_components`,
  `time_compose`, `lin`, `cyc`)
- chronon bounds (`chronon_glb`, `chronon_lub`, `chronon_common`) and circular
  sums (`circsum`)
- optional pandas `Series`/`Index` input, `PeriodIndex`/`DatetimeIndex` output,
  and `"mixtime"` ExtensionArray columns for Series/DataFrame, including
  chronological sorting, filtering, `between`, `min`/`max`, grouping, merging,
  de-duplication, concatenation, and Arrow/Parquet round-trips
- the low-level Rust chronon splits

Not yet ported:

- Symmetry454, civil/lunar/solar/astronomical calendars
- the full R format-token language and all labelled parsing variants
- the complete vctrs/S7 coercion surface
- ggplot2 and tsibble integration
- complete `Mixtime` arithmetic beyond duration shifts and time-point
  differences; full non-pandas columnar coercion remains incomplete
- shifts requiring a fractional month and R's alternative `on_invalid` DST
  resolutions
- shifts from calendar chronons to finer fixed units (for example,
  `yearmonth + days(1)`)
- R's `seq(from, length.out=, by=)` form

See [`COVERAGE.md`](COVERAGE.md) for the R branch-to-test map and
[`DECISION.md`](DECISION.md) for the scope decision.
