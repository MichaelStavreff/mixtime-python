# mixtime-python

A Rust + Python port of the Gregorian chronon arithmetic from R's
[**mixtime**](https://github.com/mitchelloharawild/mixtime) package.

The Rust crate provides the conversion kernels and a PyO3 extension. The
Python package is imported as `mixtime` and accepts and returns NumPy arrays
with zero-copy input and direct output fills.

> **Status:** early-stage port. Only the four Gregorian `chronon_divmod` splits
> are implemented; the rest of mixtime is out of scope. See [Scope](#scope).

## What it does

mixtime represents time points as counts of *chronons* — for example days,
months, or years. This port converts between day, month, quarter, and year
chronons using the same Gregorian calendar arithmetic as the R package.

It is a low-level kernel, not a full replacement for mixtime's R API. It does
not provide time vectors, parsing, formatting, timezone handling, or calendars
other than Gregorian.

## Quick start

Prerequisites:

- Rust toolchain (`cargo`, `rustc`)
- Python 3.9+
- [`uv`](https://docs.astral.sh/uv/)
- `just` (optional)

```sh
git clone https://github.com/MichaelStavreff/mixtime-python.git
cd mixtime-python/python
uv sync --reinstall-package mixtime-rs
```

`uv sync` builds the Rust extension with maturin and installs the local
`mixtime` package into the project environment. Run it from `python/`; the
Python project lives there, and the Rust crate is resolved as a path
dependency. `pip install` is not supported for the same reason.

Run Python inside the project environment with `uv run`:

```sh
uv run python -c "import mixtime; print(mixtime.__all__)"
```

### Optional: the `just` task runner

The repository includes a [`justfile`](justfile) for
[`just`](https://github.com/casey/just), a small command runner. It is a
convenience only; the underlying commands are shown in the Quick start and
Development sections.

```sh
just build   # cd python && uv sync --reinstall-package mixtime-rs
just test    # cargo test, then rebuild the extension and run pytest
```

## Usage

```python
import numpy as np
import mixtime

days = np.array([0.0, 59.0, 60.0, 365.0])
months, offsets = mixtime.day_to_month(days)

print(months)
print(offsets)
```

Each function takes a one-dimensional `float64` NumPy array and returns two
`float64` arrays, `(div, mod)`:

- `div` is the index of the containing target granule.
- `mod` is the offset from the start of that granule, in source chronons.
  For `month_to_day` and `year_to_day`, `mod` is always zero.

The input buffer is read directly, without a copy, and the output arrays are
filled directly by the Rust kernel. Python lists are rejected rather than
silently converted.

### API

| Function | Conversion |
|---|---|
| `day_to_month(x, from_n=1.0, to_n=1.0)` | day → month |
| `day_to_quarter(x, from_n=1.0)` | day → quarter (3-month blocks) |
| `day_to_year(x, from_n=1.0, to_n=1.0)` | day → year |
| `month_to_day(x, from_n=1.0, to_n=1.0)` | month → day |
| `year_to_day(x, from_n=1.0, to_n=1.0)` | year → day |

`from_n` and `to_n` are granule sizes, matching the `n` field of mixtime's time
units. For example, `from_n=2` means 2-day or 2-month units.

## Scope

Ported:

- day → month, including quarters (`to_n = 3`)
- day → year
- month → day, including multi-month `from_n`
- year → day, including `from_n` and `to_n` scaling

Not ported:

- parsing, formatting, and timezone handling
- astronomical calendars and non-Gregorian calendar systems
- cardinality algebra and BC/AD labels
- the generic `chronon_divmod` dispatch and the rest of the mixtime API

See [`COVERAGE.md`](COVERAGE.md) for the R branch-to-test map and
[`DECISION.md`](DECISION.md) for the scope and performance decision.

## Development

### Tests

```sh
# Rust
cd rust && cargo test

# Python (builds the extension first)
cd python && uv sync --reinstall-package mixtime-rs && uv run pytest
```

Or, with `just`:

```sh
just test
```

The suite is 14 Rust tests and 19 Python tests. Fixtures under `fixtures/` were
generated by running R mixtime 0.4.0. See
[`CONTRIBUTING.md`](CONTRIBUTING.md) for the upstream sync procedure.

### Benchmarks

`benchmarks/` contains the R and Python/Rust benchmark scripts. The port is
faster than R at every measured size from 0 to 2,097,152 elements; see
[`DECISION.md`](DECISION.md) for the raw results.
